# ブラウザ利用者役エージェント

人がエディターを使うときの「読む → 操作する → 結果を見る」を、実際のReact画面とMonaco上で実行します。アプリの内部ストアやMonaco APIを直接操作しません。

## 起動

```powershell
npm run dev -w apps/web
```

別ターミナルで実行します。バックエンドサーバーは不要です。ブラウザはインストール済みのEdge、Chrome、Playwright Chromiumの順に探します。

```powershell
npm run dogfood:ui
npm run dogfood:ui -- --headed
npm run dogfood:ui -- --only search-return,quick-open-type
npm run dogfood:ui -- --url http://127.0.0.1:5173 --out docs/dogfood/my-run
```

通常モードは10個の操作シナリオを再実行します。AI呼び出しは不要で、失敗があれば終了コード1になります。保存・未保存変更の保護・検索の状態保持・通信エラーと遅延・キーボードでのファイル選択・入力先の復帰を確認します。

## AIによる自由探索

```powershell
npm run dogfood:ui -- --explore --steps 12
npm run dogfood:ui -- --explore --model sonnet --steps 20 --goal "ファイルを探して編集・保存し、左右に分割して比較してください。迷った点を記録してください。"
```

既存のClaude Agent SDKとログインを使用します。モデルへ毎回スクリーンショット、画面のアクセシビリティツリー、表示中の操作対象一覧、直前までの操作履歴を渡します。AIはクリック・文字入力・キー操作・選択・スクロール・終了から次の1操作を選び、結果を見て再判断します。

モデルがコードやシェルを実行する道具はありません。1回の判断には90秒の上限、全体には操作回数の上限（1～50、既定12）があります。モデルが利用できない場合は明示的に失敗します。操作上限で終わった場合は「目的達成」とせず、その状態を記録します。自由探索はモデル利用量が発生します。

## 検証環境と出力

バックエンド境界だけを置き換え、3ファイルを持つ検証用プロジェクトを毎回作ります。保存はメモリ上のファイルに反映し、画面から再度開いて確かめます。HTTP APIとアプリのWebSocketは遮断・置換され、未対応操作は実サーバーへ通しません。自由探索では別オリジンへのHTTPアクセスも遮断します。

実行結果は既定で `docs/dogfood/browser-<日時>/` に保存されます。

| ファイル | 内容 |
| --- | --- |
| `report.md` | 目的・再現手順・成功/失敗・証拠へのリンク |
| `report.json` | 通常モードの機械可読結果 |
| `history.json` | 自由探索の判断・操作・失敗・終了理由 |
| `*.png` / `*.yml` | スクリーンショットと画面の読み取り |
| `*.zip` | Playwrightの操作トレース（ローカル保存、Git対象外） |

通信遅延・通信失敗は検証用に注入した条件です。その条件下でUIがどう見えるかを調べています。実バックエンドの検索・保存の正しさや、実プロジェクトでの長時間使用、未知の問題の網羅性を保証するものではありません。AIの自由探索の指摘は候補として扱い、再現できたものを修正します。

## 今回の改善

改善前は8シナリオ中6シナリオで問題を再現し、改善後は同じ8シナリオがすべて成功しました。追加したEsc・Tabのフォーカス確認2件も成功しました。

| 確認した不満 | 改善 |
| --- | --- |
| 検索→ファイル→検索で入力と大小文字設定が消える | 同じタスクでのタブ往復は検索パネルの状態を維持 |
| 検索失敗時に前の検索結果が残る | 結果・エラーを検索条件に結び付け、古い結果を非表示 |
| 次の検索中も前の結果をクリックできる | 入力直後から待機状態を表示し、現在の条件の結果だけ表示 |
| Ctrl+Pで開いた直後／同じファイルを選び直した後に入力できない | ファイルを開くたびに本文へのフォーカス要求を伝達 |
| ファイル一覧の読込中に↓を押すとEnterで開けない | 候補選択位置を0未満にしない |

さらに、ファイル選択のEscで元の入力先へ復帰し、Tabで背面へ移動しないようにしました。候補と入力欄をアクセシビリティ属性で関連付けています。
