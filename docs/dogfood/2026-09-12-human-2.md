## この会話で直したもの

1. **VS Code で動かしたタスクのファイルは、終わっていても直せなかった**（常に「閲覧」、保存ボタンが押せない。理由は下の小さな一文だけ）。
   利用者のタスクの多くは VS Code 由来なので、エディタが実質読むだけになっていた。
   → エージェントが作業している間だけ閲覧のみにした。外部のタスクで保存した時の年表の補足は
   「Tower から指示を送る時に伝える（VS Code で続ける場合は伝わらない）」と正直に書く。
2. **左右に分割した狭い欄で、ボタンの文字が途中で折れた**（「閉じ／る」「文字のま／ま」「保存（Ctrl+／S）」）。
   → ボタンの文字は折らず、入りきらない時はボタンごと次の行へ送る。
3. **Git の欄が、タスクを選ぶたびに約 1.8 秒「変更を読み込み中…」だった**（変更 64 件のリポジトリ）。
   変更ファイル 1 件ごとに git を起動していた（1 回 0.1 秒）。
   → 差分を 1 回でまとめて取り、ファイルごとに分ける（0.36〜0.42 秒）。名前だけ変えたファイルは「名前だけ変わりました」と出す（前は空だった）。
   単体テストを追加（改名・削除・空白入りの名前・日本語の名前・本文に見出しそっくりの行）。

## 別の会話が今直しているもの（そちらに渡したい所見）

- 4分割で判断待ちの「開いて答える」を押しても、画面がまったく変わらない（#99b25c そのもの。そのタスクがパネル 3 に出ていても印も付かない）
- 「ファイル＋チャット」なのに左はエクスプローラーではなく判断インボックス。空の編集領域には同じ案内が 2 つ（「このグループを選んで…」「左のエクスプローラーで…」）
- 編集領域の上の帯があふれて「タスクに戻る」だけ 2 行目に落ちる（1400px 幅・チャットあり）
- 4分割の各パネルは「VS Code で動いています…」の注意と 1 行に畳まれた報告だけで、判断に要る報告の中身が見えない
- 判断インボックスの札が縦に長く、3 件で画面が埋まる
- スマホ幅でも左の縦の帯（判断待ち・ファイル・検索…）が出て幅を取る。下のタブ「ワークスペース」が判断待ちのことだと分かりにくい
